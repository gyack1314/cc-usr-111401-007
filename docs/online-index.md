# 在线二级索引设计约定

在 `table.py` 的已提交变更序列、快照读和旧像校验之上，提供可在线建立、
可重启续建的 `(tool, occurred)` 二级索引。构建期间入仓不暂停，查询始终
保留扫表旧路径。

## 组件与持久化

- `repo.py`：提交日志内容寻址（每个 commit 是对象仓里的不可变对象），
  目录引用 `table/head` 用 CAS 推进；`Repository.open` 仅凭目录与对象仓
  即可重建整张 Table 和任意历史快照。
- `paged.py`：分页不可变索引。清单记录每页的内容寻址 digest 与首行锚点，
  范围查询用锚点二分定位入口页，只读取命中页；`fetched_pages` 可核对
  选择性访问是否真正减少。
- `online.py`：构建状态机，状态对象本身内容寻址并挂在 `build/state`：
  - `scanning`：基线快照在构建开始时冻结，按 row_id 切成互斥不相交的
    下标区间，由有界线程池并发扫描，进度 `scan_cursor/segments` 落盘；
  - `catching_up`：严格按提交序号单车道应用基线之后的提交，水位
    `watermark` 单调推进，每个提交恰好应用一次；
  - `active`：覆盖证明通过并 CAS 换入 `build/active` 后一次性落盘；
  - `failed`：候选保留但永不参与查询，`resume` 可复用已完成进度续建，
    `abandon` 显式废弃；`abandoned` 由新一轮构建原子替换，引用不留空窗。
- `planner.py`：查询计划。只有当活动索引清单水位等于读句柄序号，且
  重放的行袋与该序号真实快照逐行一致时才走索引；否则扫表。
- `scheduler.py`：守护线程轮询驱动状态机；活动索引落后于表头时自动
  开启下一轮构建。线程退出不影响已落盘状态与扫表查询。

## 关键正确性约束

1. 扫描/追平交界的更新与删除不会漏、不会重：基线行先归并，追平的整行
   覆盖与墓碑最后生效；变更按 row_id 处理，不依赖旧键反查，因此键和
   分区（tool）同时改变也不会留旧键或重复返回。
2. 覆盖证明是启用与查询选路的唯一依据：索引文件存在、追平队列为空都
   不构成覆盖。证明核对行袋、身份唯一性、清单水位与排序内容，并随
   状态落盘。
3. 旧读句柄不套用只代表最新状态的索引：水位晚于或早于读快照都回退扫表；
   越界序号直接报错。
4. 活动引用只允许更高或相等水位换入，旧水位候选即使证明有效也回到追平，
   不会覆盖更新的索引。
5. READY 只是 `promote` 内的内存瞬态，不持久化；外部可见状态只有
   scanning/catching_up/active/failed/abandoned，崩溃恢复靠已落盘的
   追平状态重放证明（全部中间产物内容寻址、操作幂等）。
6. 构建失败、无候选、索引对象损坏均可扫表，功能不依赖索引可用性。
